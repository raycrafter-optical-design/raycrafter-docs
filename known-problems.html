Known problems

RayCrafter is pre-alpha. These are the known problems in v0.0.4 at the time of writing; the current list is on GitHub under the known problem label.

Zemax files

  • Exported ZMX files look wrong when opened in Zemax. Even a single achromat appears with very thick, elongated surfaces. Do not rely on exported files yet. #9
  • Fields do not survive a ZMX export and import. A ZMX file holds one aperture, one object distance, and a list of angles and wavelengths, so per-field widths, vergences, offsets and colours are lost. Save a project to keep them. #11
  • Assemblies come back as separate lenses. This includes Plossl pairs. The optics are right, but the lenses no longer move as one. Save a project to keep them. #12
  • Apertures in air are not modelled. Baffles and cube faces in an imported file are left out, with a note, so RayCrafter may pass rays that Zemax blocks. #22
  • Rectangular apertures become circles. An imported rectangular aperture is replaced by the circle that fits inside it, so rays near the corners are blocked. #23
  • Folded paths are not supported. Files with mirrors do not import, and folded paths cannot be built. #60

Building a design

  • Concave lenses can be made to overlap. Dragging or placing lenses stops their centres crossing, but concave surfaces can still overlap towards the rim. Typing a gap refuses such values. #58
  • User parts cannot be renamed or deleted from RayCrafter. Delete the part’s file instead. Renaming the file does not rename the part. #62
  • Mount type is unknown for most catalogue lenses. Unknown does not mean unmounted. #59

Accuracy of the analysis

  • Collimated (afocal) output is handled poorly. Focal lengths show as infinite, and Autofocus and Lock focus move the image plane to a meaningless position. #57
  • The MTF ignores a field’s offset. Spot diagrams and ray fans include it; the MTF is calculated as if the offset at the first lens were 0. This includes the offset an angled beam picks up between the source plane and the lens. #10
  • Side view draws some totally internally reflected rays wrongly. They are drawn running on to the lens edge rather than stopping. This affects the drawing only. #16

Internal issues

These are about the code rather than what you see, but they may affect speed or reliability.

  • Extra work while editing fields. Holding an arrow on a field-window spin box makes updates roughly twice as slow as needed. #13
  • MTF workaround for an Optiland error. The code that catches an Optiland error could hide other errors. #14
  • Code layout. The Python API depends on code kept in the package for the AI agent server. #33

Reporting a problem

Please open an issue with what you did, what you expected, and what happened. A saved project file helps; note that an imported design’s project contains the original ZMX file.
